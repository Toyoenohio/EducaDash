## 🛑 FASE 0 – SEGURIDAD CRÍTICA (Prioridad máxima)

### Vulnerabilidad detectada
El archivo `.env.example` y el código del frontend usan `VITE_SUPABASE_SERVICE_ROLE_KEY`. En Vite, cualquier variable con prefijo `VITE_` se inyecta en el bundle del navegador, exponiendo una clave que **bypassea todas las políticas RLS** de Supabase. Esto permite a cualquier atacante tomar control total de la base de datos.

### Instrucciones para el agente

#### 1. Eliminar del frontend
- Eliminar por completo cualquier referencia a `VITE_SUPABASE_SERVICE_ROLE_KEY` o `import.meta.env.VITE_SUPABASE_SERVICE_ROLE_KEY` en `src/lib/supabaseClient.js` o similar.
- Asegurarse de que **solo** la `VITE_SUPABASE_ANON_KEY` se use para el cliente público.

#### 2. Implementar Edge Function segura para operaciones privilegiadas
Para el registro silencioso de alumnos (u otras operaciones que requieran la clave de servicio), crear una **Edge Function en Supabase** que actúe como proxy seguro.

**Estructura de la Edge Function (Deno/TypeScript):**

```ts
// supabase/functions/create-student/index.ts
import { createClient } from 'jsr:@supabase/supabase-js@2'

Deno.serve(async (req) => {
  try {
    const { email, password, metadata } = await req.json()
    const supabaseAdmin = createClient(
      Deno.env.get('SUPABASE_URL')!,
      Deno.env.get('SERVICE_ROLE_KEY')!   // Solo aquí, en backend
    )
    const { data, error } = await supabaseAdmin.auth.admin.createUser({
      email,
      password,
      user_metadata: metadata,
      email_confirm: true,
    })
    if (error) throw error
    return new Response(JSON.stringify({ user: data.user }), { status: 201 })
  } catch (err) {
    return new Response(JSON.stringify({ error: err.message }), { status: 400 })
  }
})

Llamada desde el frontend:
js

const { data, error } = await supabase.functions.invoke('create-student', {
  body: { email, password, metadata }
})

⚡ FASE 1 – RENDIMIENTO Y ESTABILIDAD DE DATOS (Soluciona recargas manuales y lentitud)
Diagnóstico de causas

    Ausencia de caché: Cada cambio de ruta o montaje de componente dispara consultas completas a Supabase sin límites (select('*')).

    Filtros y búsquedas en el cliente: Después de descargar miles de registros.

    Importación estática de todas las páginas: El bundle inicial incluye código de todas las vistas.

    Mala sincronización de sesión: El AuthContext actual puede provocar renders infinitos o peticiones redundantes.

2. Refactorizar hooks de datos (useAlumnos, useDashboard, usePagos)

Antes: useState + useEffect con descarga masiva.
Después: useQuery con paginación y búsquedas en BD.

Ejemplo para useAlumnos:
js

export const useAlumnos = (pagina = 1, busqueda = '') => {
  const limit = 20
  const from = (pagina - 1) * limit
  const to = from + limit - 1

  return useQuery({
    queryKey: ['alumnos', pagina, busqueda],
    queryFn: async () => {
      let query = supabase
        .from('alumnos')
        .select('*', { count: 'exact' })
        .range(from, to)
        .order('nombre')
      if (busqueda) {
        query = query.ilike('nombre', `%${busqueda}%`)
      }
      const { data, count, error } = await query
      if (error) throw error
      return { data, total: count }
    },
    keepPreviousData: true,
  })
}

5. Corregir sincronización de sesión (AuthContext)

Revisar AuthContext para evitar:

    Peticiones repetitivas a supabase.auth.getSession().

    Estados de carga infinitos cuando el usuario no está autenticado.

Mejora sugerida (usando onAuthStateChange una sola vez):
js

useEffect(() => {
  const { data: listener } = supabase.auth.onAuthStateChange((event, session) => {
    setSession(session)
    setLoading(false)
  })
  return () => listener?.subscription.unsubscribe()
}, [])

Criterio de éxito: Navegar entre secciones y esperar 10 minutos; al volver a una pestaña anterior, los datos aparecen sin recargar la página.
